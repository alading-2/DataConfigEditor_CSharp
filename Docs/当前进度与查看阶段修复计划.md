# 当前进度与查看阶段修复计划

> **Last Updated:** 2026-04-25

## 当前进度

DataConfigEditor 当前已经完成第一阶段工作区表格浏览器的大部分能力：

- 可打开工作区目录，并在左侧显示配置相关 `.cs` 文件。
- 可隐藏 `bin/`、`obj/`、`.git/`、`.uid` 等无关项。
- 点击配置 `.cs` 后，右侧以表格方式展示静态实例和 public 属性。
- 表头已显示 C# 属性名和 `<summary>` 中文说明。
- 可加载类型 DLL，用于补充 enum、bool、数值、string 等类型元数据。
- 已有搜索、排序、列筛选、设置面板和基础布局设置。

当前阶段仍然是查看器，不做编辑、撤销重做、保存回写。

## 本阶段问题

截图中 `AbilityLevel` 显示为 `(`、`EntityType` 显示为 `E`，根因不是单纯“DLL 没加载好”，而是源码表达式被解析截断：

- `(int)DataKey.AbilityLevel.DefaultValue!` 被截成 `(`。
- `EntityType.Ability` 被截成 `E`。
- DLL 只能补充“这一列是什么类型”，不能修复已经被截断的原始表达式。

因此查看阶段需要先保证源码解析器保留完整表达式，再用 DLL 和 DataKey 源码补语义。

## 已修复内容

- `SourceParser` 保留完整属性默认值表达式。
- 表格单元格继续保留原始表达式 `RawValue`，显示值 `Value` 单独格式化。
- `CsTableParser` 对 enum 显示成员名，而不是完整表达式。
- 新增 DataKey 默认值解析：从同级 `DataKey/` 目录扫描 `DataMeta.DefaultValue`，用于显示 `(type)DataKey.X.DefaultValue!` 的实际默认值。
- 字符串显示去掉 C# 引号，并修复 `res://` 被误认为行注释导致路径只显示 `res` 的问题。
- 类型 DLL 会解析 `const string` 和可读取的 `static readonly string`，用于把 `FeatureId.Ability.Active.Slam` 这类静态 ID 显示为最终字符串值。
- 列头点击已改为筛选入口，并按 enum、bool、数值、文本列限制可用筛选类型。
- 筛选重绘后会恢复当前行列、首个可见行列和水平滚动位置，不再直接跳回表格左上角。
- 已新增表格查看体验排查文档：`Docs/表格查看体验问题排查与改进计划.md`。

## 下一步

查看阶段继续按以下顺序推进：

1. 增加列头筛选状态：有筛选的列需要可见标识和 tooltip 条件说明。
2. 修复表头/第一行显示问题：Key 截断、表头高度、换行和空行问题优先处理。
3. 扩展 DataKey 解析范围：读取 `DisplayName`、`Description`、`MinValue`、`MaxValue`、`Category`，用于表头 tooltip 和后续诊断。
4. 增强表达式显示：数值统一格式、Flags enum 组合显示、无法解析表达式显示诊断。
5. 增强类型解析：处理全局命名空间、同名类型冲突、泛型/列表只读降级、缺失 DLL 的清晰提示。
6. 增加查看验收样例：以 `参考/DataNew/Ability/AbilityData.cs`、`UnitData.cs`、`EnemyData.cs` 作为固定回归样例。
7. 查看稳定后再进入编辑阶段：类型化编辑、撤销重做、保存回写。

## 验收标准

- 打开 `AbilityData.cs` 后，`AbilityLevel` 显示 `1`，`AbilityMaxLevel` 显示 `10`。
- `EntityType.Ability` 显示为 `Ability`，不再显示 `E`。
- `AbilityType`、`AbilityTriggerMode`、`AbilityCostType` 等 enum 列显示成员名。
- 未显式赋值但有 `DataKey.X.DefaultValue` 的单元格显示 DataKey 默认值。
- 无法解析的表达式保留原始表达式，不显示截断字符。
