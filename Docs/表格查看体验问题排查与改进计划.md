# 表格查看体验问题排查与改进计划

> Last Updated: 2026-04-25

## 目标

当前阶段只把 DataConfigEditor 的查看能力做稳，不进入编辑、保存、撤销重做。表格体验先对齐 Excel/常见数据表控件的查看习惯：筛选入口容易找到、筛选条件按列类型收敛、筛选后不丢上下文、已筛选状态清楚可见。

## Excel 类行为基准

- 筛选入口位于列头，不要求用户先选中单元格再去工具栏找按钮。
- 根据列内容/类型提供不同筛选能力：文本列走文本筛选，数值列走数值比较，枚举/布尔列走离散值勾选或等值筛选。
- 筛选操作隐藏不匹配的行，但用户的横向位置、当前列和附近行上下文不应跳回左上角。
- 筛选结果为 0 行时仍然保留列头，用户不能因为无匹配数据而失去当前列上下文。
- 已筛选列需要有可见状态，用户应能快速看出哪些列正在影响结果。
- 清除筛选应同时支持清除当前列和清除全部筛选。
- 排序和筛选是两个独立意图，普通点击列头不应因为误触导致表格刷新、排序或丢失位置。

## 已发现问题

### P0：筛选后跳回左上角

根因：筛选会调用 `RenderCurrentTable()`，该方法重新构建整个 `DataGridView`。旧实现中 `SheetBuilder.BuildGrid()` 在每次构建后执行：

```csharp
grid.ClearSelection();
grid.CurrentCell = grid.Rows[0].Cells[0];
```

这会清空原来的水平滚动、垂直滚动、当前行和当前列，导致用户在表格后半段筛选后直接回到初始位置。

处理：重绘前保存视口快照，重绘后按行名/列 Key 恢复；如果当前行被筛掉，则保持原来的首行位置附近，不回到 0,0。

补充修复：筛选结果为 0 行时，`DataGridView` 仍然构建列头并保存当前列、首个可见列和水平滚动；清除筛选后按同一列位置恢复，不再回到前面的列。

### P1：筛选入口和状态还不够像表格工具

当前已支持点击表头打开筛选，但还缺少持续可见的列头筛选状态。下一步应该在列头增加轻量状态提示，例如不同背景色、tooltip 追加筛选条件，或后续接入真正的筛选图标绘制。

### P1：筛选面板需要继续收敛交互

已做类型感知筛选，但仍需要继续检查：

- enum/bool 应优先显示离散值菜单，不进入复杂对话框。
- 数值列只显示等于、不等于、大于、小于、区间、空值、非空。
- 文本列只显示包含、等于、不等于、空值、非空。
- 不支持的筛选类型不应该显示为可选项。

### P1：表头布局和第一行可读性

已知问题包括第一行 Key 显示不全、表头摘要占用高度后文本截断、中间空行/间距异常。后续需要单独处理列头布局策略：

- 属性名和中文 summary 的显示比例。
- 表头高度和换行规则。
- 超长文本 tooltip。
- 是否固定实例名列并保持横向滚动时的可读性。

### P2：列宽和长文本策略

当前超长值暂不处理，但需要规划：

- 默认列宽不能让常见 Key 被截断得不可识别。
- 长值保留单行，tooltip 显示完整 RawValue。
- 提供自动适配可见单元格、固定宽度两种模式。

## 本次修复

- 新增 `TableGridViewport` 纯逻辑，用于根据旧视口快照和新表格行列计算恢复目标。
- `RenderCurrentTable()` 在重建表格前捕获：
  - 当前行名和当前列 Key。
  - 首个可见行名和首个可见列 Key。
  - 当前行列索引。
  - `HorizontalScrollingOffset`。
- 重建后恢复：
  - `CurrentCell`。
  - `FirstDisplayedScrollingRowIndex`。
  - `FirstDisplayedScrollingColumnIndex`。
  - `HorizontalScrollingOffset`。
- `SheetBuilder` 不再强制把当前单元格设为左上角。
- 增加单元测试覆盖：
  - 当前行列仍存在时按身份恢复。
  - 当前行被筛掉时保留原位置附近。

## 下一步顺序

1. 增加列头筛选状态：有筛选的列用稳定视觉提示和 tooltip 展示条件。
2. 梳理表头点击区域：区分打开筛选、排序、普通选列，避免误触刷新。
3. 修第一行/表头显示不全：先固定高度和换行规则，再处理超长值。
4. 增加“清除当前列筛选”和“清除全部筛选”的显眼入口。
5. 增加表格 UX 回归清单：筛选、搜索、排序、切文件、加载 DLL、改设置后都不应意外丢失视口。
