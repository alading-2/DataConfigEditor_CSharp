# 工作区表格浏览器执行方案

日期：2026-04-23
对应设计：`docs/superpowers/specs/2026-04-23-workspace-table-browser-design.md`
目标：将现有原型改造成“目录工作区 + 只读表格查看器”

## 1. 执行原则

- 先修正工程边界，再做功能开发。
- 先让工具独立可构建、可运行，再谈 DLL 和强类型语义。
- 第一阶段坚持只读表格查看，不回退到代码编辑器。
- 所有新增结构优先为后续 Roslyn/强类型能力预留接口。

## 2. 当前阻塞结论

现阶段的直接阻塞不是“缺 DLL 资源”，而是项目本身无法稳定构建。

已验证问题：

- `DataConfigEditor.csproj` 当前将 `Src/Data/**` 一并编译。
- 这些文件依赖 `Godot`、`ExportAttribute`、`DataKey` 等外部定义。
- `dotnet build` 已出现大量编译错误。

因此执行顺序必须调整为：

1. 切断工具项目与样例/游戏源码的编译耦合。
2. 让工具项目先能单独 build/run。
3. 再实现工作区目录树和表格加载。

## 3. 实施阶段

### 阶段一：修复工程边界

目标：

- 只让工具代码参与编译。
- 样例或历史数据文件只作为解析输入，不作为工具程序集源码。

任务：

- 审查 `DataConfigEditor.csproj` 的默认 `Compile` 包含范围。
- 将工具代码和样例数据分离。
- 必要时增加 `Compile Remove` 或重组目录。
- 验证 `dotnet build` 不再因 `Godot` 相关类型报错。

产出：

- 可构建的工具项目。
- 一份记录构建边界调整原因的说明。

### 阶段二：工作区入口与状态持久化

目标：

- 软件可打开任意目录。
- 支持命令行参数目录。
- 支持最近目录。

任务：

- 定义启动参数处理。
- 增加“打开目录”主入口。
- 定义最近目录存储格式和位置。
- 欢迎态展示最近目录列表。

产出：

- 手动打开目录可用。
- 参数打开目录可用。
- 最近目录持久化可用。

### 阶段三：左侧目录树

目标：

- 建立类似 VS Code 的基础工作区树。

任务：

- 扫描目录结构。
- 过滤仅显示文件夹与 `.cs` 文件。
- 处理展开、折叠、选择状态。
- 将树节点和真实路径建立映射。

产出：

- 左侧目录树可浏览。
- 点击节点可定位文件。

### 阶段四：右侧表格文档模型

目标：

- 建立 UI 无关的表格中间模型。

任务：

- 设计 `TableDocument`、`TableColumn`、`TableRow`、`ParseDiagnostic`。
- 调整当前解析逻辑输出统一模型。
- 将 ReoGrid 构建逻辑改为消费该模型。

产出：

- UI 与解析逻辑解耦。
- 后续替换解析器不需要重写 UI。

### 阶段五：单文件解析与提示态

目标：

- 点击 `.cs` 文件时显示表格或不可解析提示。

任务：

- 将当前“按目录扫描类型”的逻辑改成“按单文件解析”。
- 能识别配置类、属性、静态实例、注释、分组。
- 对无法成表的文件输出明确诊断。

产出：

- 表格态可显示。
- 提示态可显示。
- 解析失败不会拖垮整个工作区。

### 阶段六：VS Code 任务与文档补充

目标：

- 提供一键测试入口。
- 让后续开发步骤标准化。

任务：

- 新增 `.vscode/tasks.json`
- 至少包含：
  - `build`
  - `run`
  - `run:test-data`
- `run:test-data` 传入测试路径：
  `E:\Godot\Games\MyGames\复刻土豆兄弟\brotato-my\Data\DataNew`
- 更新相关文档，说明参数启动与最近目录行为。

产出：

- VS Code 内可一键构建和测试启动。
- 文档与实际行为一致。

### 阶段七：表格显示设置

目标：

- 解决表格贴近顶部导致视觉上像被遮住的问题。
- 提供常规软件里的“设置”菜单，让用户自行调整表格显示效果。
- 设置持久保存，下次启动自动恢复。

任务：

- 新增 `设置` 菜单入口。
- 新增 UI 设置模型与 JSON 持久化存储。
- 支持调整：
  - 表格顶部留白
  - 表格字体大小
  - 表格行高
  - 固定列宽
  - 列宽固定/自动适配策略
- 设置修改后立即应用到当前表格，并保存到本地用户目录。

产出：

- 表格位置可根据用户偏好下移。
- 表格字号、行高、列宽可调整。
- UI 偏好保存到 `%LocalAppData%\DataConfigEditor\ui-settings.json`。

## 4. 建议文件改造方向

建议按职责新增或调整以下模块：

- `Src/Workspace/WorkspaceService.cs`
- `Src/Workspace/RecentDirectoryStore.cs`
- `Src/Documents/TableDocument.cs`
- `Src/Documents/TableColumn.cs`
- `Src/Documents/TableRow.cs`
- `Src/Parsing/CsTableParser.cs`
- `Src/UI/WorkspaceTreeBuilder.cs`

现有文件预计改造重点：

- `Src/MainForm.cs`
- `Src/Core/ConfigTypeScanner.cs`
- `Src/UI/SheetBuilder.cs`
- `Src/Program.cs`
- `DataConfigEditor.csproj`

## 5. 验证顺序

每个阶段建议都做最小验证，不要等到最后一起验证。

推荐验证顺序：

1. `dotnet build`
2. 软件可启动
3. 手动打开目录
4. 参数打开目录
5. 左侧目录树显示正确
6. 点击 `.cs` 文件出现表格或提示态
7. 最近目录可保存和恢复
8. 表格设置修改后立即生效
9. 重启软件后表格设置自动恢复

## 6. 暂不实施项

以下内容先不进入当前执行批次：

- 保存回写 `.cs`
- 枚举下拉和强类型编辑器
- 图片预览
- DLL 加载
- Roslyn 语义分析
- MSBuildWorkspace
- Godot 工程绑定

## 7. 风险控制

- 如果工程边界不先修，后续所有阶段都会反复被构建错误打断。
- 如果 UI 直接依赖当前解析器结构，后续切 Roslyn 成本会升高。
- 如果第一阶段混入编辑能力，范围会明显失控。

## 8. 完成定义

执行方案完成时，应达到以下结果：

- 工具项目可单独构建并启动。
- 可通过按钮或参数打开目录。
- 左侧是文件夹和 `.cs` 文件树。
- 点击 `.cs` 文件后右侧只显示表格或提示态。
- VS Code 任务可直接启动测试目录。
- 顶部 `设置` 菜单可调整表格顶部留白、字体、行高、列宽，并持久保存。

## 9. 后续衔接

本执行方案完成并经确认后，下一步应输出正式实施计划，按阶段拆成可执行任务，再进入代码修改。

## 10. 开发入口

开发阶段统一使用以下入口：

- `dotnet build DataConfigEditor.sln`
- `dotnet run --project DataConfigEditor.csproj`
- VS Code task: `run:test-data`

命令行参数路径优先于最近目录恢复。第一阶段不自动打开固定路径，固定测试目录只通过 task 或显式参数进入。
